# シフト表アプリ ChatGPT用プロンプト集

このファイルは、これまでのやり取りで作った「シフト表アプリ（MVP）」を、ChatGPTでも同じように作れるようにまとめたものです。

## 結論：1回では作らず、6ステップに分けてください

全部を1回で頼むと、ChatGPTは途中で文章が切れたり、ファイル同士の関数名がずれたりしやすくなります。
**最初に「仕様書」を渡して、ファイルを1つずつ作らせる**のが一番確実です。

| ステップ | ChatGPTに貼るもの | できるもの |
|---|---|---|
| 1 | 【プロンプト1】仕様書 | 「了解」の返事（まだコードは出さない） |
| 2 | 【プロンプト2】 | `common.js` と `style.css` |
| 3 | 【プロンプト3】 | `input.html`（シフト入力） |
| 4 | 【プロンプト4】 | `day.html`（1日の階段状シフト表） |
| 5 | 【プロンプト5】 | `week.html`（週間シフト）と `index.html` |
| 6 | 【プロンプト6】 | 動作チェックと修正 |

最後に「WEBで公開する手順」を見て、ネットに公開します。

### 進め方のコツ

- **同じチャットの中で**、プロンプト1から順番に貼ってください（別のチャットにすると仕様書を忘れます）。
- 返事のコードは**ファイル名どおりに1つずつ保存**してください（例：メモ帳に貼って `common.js` という名前で保存）。5つのファイルは**全部同じフォルダ**に入れます。
- コードが途中で切れたら「続きを、切れたところから出してください」と送ります。それでもおかしい場合は「〇〇.html を最初から全部、省略せずに出し直してください」と送ります。
- 「…（省略）」「既存のコードはそのまま」のような省略が入っていたら、そのファイルは使えません。「省略せずに全文を出してください」と頼み直してください。

```
あなたはWebアプリを作るプロのエンジニアです。
これから、飲食店などで使う「アルバイトのシフト表アプリ（MVP）」を一緒に作ります。
まず下の仕様書をすべて読んで覚えてください。

# 仕様書

## 0. 全体のルール
- HTML / CSS / JavaScript だけで作る。サーバー、データベース、ログイン、外部ライブラリ、ビルドツールは使わない。
- 文字はすべて日本語。文字コードは UTF-8。
- データはブラウザの localStorage に保存する（この端末のブラウザだけに保存される。これはMVPの仕様として受け入れる）。
- ファイルは次の6つで、すべて同じフォルダに置く。
  - common.js（全ページ共通の処理）
  - style.css（全ページ共通の見た目）
  - input.html（シフト入力ページ）
  - day.html（1日の階段状シフト表）
  - week.html（週間シフト）
  - index.html（week.html へ自動で移動するだけ）
- 各HTMLは <link rel="stylesheet" href="style.css"> と <script src="common.js"></script> を読み込み、その後に自分専用の <script> を書く。
- コードは毎回、省略なしの全文を出す。「…」「省略」「前と同じ」は禁止。
- スマホでも見られるように <meta name="viewport" content="width=device-width,initial-scale=1"> を入れ、横に長い表は横スクロールできる箱（class="scroll"）に入れる。

## 1. 定数（common.js）
- OPEN_HOUR = 9（営業開始 9時）
- CLOSE_HOUR = 22（営業終了 22時）
- STEP_MIN = 30（時間の刻みは30分）
- STORE_KEY = 'shiftApp.v1'（localStorage のキー）
- COLORS = ['#4f8cff','#ff7a59','#2bb673','#a66cff','#f5b700','#ff5fa2','#00b8d9','#8d6e63','#5c6bc0','#ef5350']
  （アルバイトさんを登録した順に色を割り当てる。11人目からはまた1色目に戻る）

## 2. データの形
localStorage['shiftApp.v1'] に次のJSONを保存する。
{
  "staff":  [ { "id": "文字列", "name": "山田", "color": "#4f8cff" } ],
  "shifts": [ { "id": "文字列", "staffId": "staffのid", "date": "2026-11-16", "start": "09:00", "end": "14:00", "note": "メモ（空でもよい）" } ]
}
- date は "YYYY-MM-DD"、start / end は "HH:MM"（2桁ゼロ埋め）。
- id は Date.now().toString(36) + ランダム文字列 で作る。

そのほかに localStorage へ保存するもの（画面の設定）：
- 'shiftApp.me'：シフト入力ページで最後に選んだ名前のid
- 'shiftApp.need'：1日のシフト表の「必要人数」（初期値 2）
- 'shiftApp.onlyWorking'：週間シフトの「出勤者のみ表示」（'1' か '0'）

## 3. common.js に入れる関数（名前を必ずこの通りにする）
- loadData()：localStorage から読む。壊れている・空のときは {staff:[], shifts:[]} を返す（try/catch で守る）。
- saveData(d)：localStorage に保存する。
- uid()：idを作る。
- toMin("09:30") → 570（分に変換）
- toHHMM(570) → "09:30"
- shortTime("09:00") → "9"、shortTime("09:30") → "9:30"（表示用。分が00なら時だけ）
- timeOptions()：9:00 から 22:00 まで30分刻みの "HH:MM" の配列（9:00 と 22:00 を両方含む）
- hoursOf(shift)：そのシフトの時間数（例 9:00-14:00 → 5）
- ymd(Date) → "YYYY-MM-DD"、parseYmd("YYYY-MM-DD") → Date（必ずローカル時間で作る。new Date("2026-11-16") は時差でずれるので使わない）
- addDays("YYYY-MM-DD", n) → n日後の "YYYY-MM-DD"
- mondayOf("YYYY-MM-DD") → その週の月曜日（週は月曜はじまり・日曜おわり）
- WD = ['日','月','火','水','木','金','土']
- labelDate("2026-11-16") → "11/16(月)"
- wdClass(日付)：土曜なら 'sat'、日曜なら 'sun'、それ以外は ''
- today()：今日の "YYYY-MM-DD"
- param(name)：URLの ?date=... などを読む
- staffById(data, id)
- esc(文字列)：HTMLに出す前に & < > " ' を変換する（名前・メモは必ずこれを通す）
- renderNav(今のページのファイル名)：画面の一番上に固定の黒いメニューを作る。左に「シフト表」、その右に「シフト入力」(input.html)「1日のシフト表」(day.html)「週間シフト」(week.html) のリンク。今いるページのリンクは色を変える。
- exportJson()：全データを shift-YYYY-MM-DD.json としてダウンロードする。
- importJson(file, 完了したときの関数)：JSONファイルを読み、staff と shifts が配列でなければ「ファイルの形式が正しくありません」と出す。正しければ「現在のデータを読み込んだデータで置き換えます。よろしいですか？」と確認してから保存する。

## 4. シフト入力ページ（input.html）
上から順に、白いカードを4つ並べる。

カード1：名前
- 「名前」のプルダウン（登録済みの人）。1人もいないときは「（先に名前を登録してください）」と表示。
- 「新しく名前を登録」の入力欄と「登録」ボタン。空欄なら「名前を入力してください」、同じ名前があれば「その名前はすでに登録されています」と出す。登録したらその人を選んだ状態にする。
- 前回選んだ人（'shiftApp.me'）を最初から選んでおく。

カード2：シフトを追加
- 「日付」（type="date"。URLに ?date= があればその日、なければ今日）
- 「開始」プルダウン：9:00〜21:30（30分刻み）。初期値 09:00
- 「終了」プルダウン：9:30〜22:00（30分刻み）。初期値 14:00
- 「メモ」（任意）
- 「シフトを追加」ボタン（青く目立たせる）
- 「よく使う時間」ボタン：9-14、10-15、12-17、14-19、17-22、9-17、13-22。押すと開始・終了のプルダウンに入る。
- 「同じ時間で週の複数日にまとめて入れる」：月火水木金土日のチェックボックス（土は青字、日は赤字）と「選んだ曜日にまとめて追加」ボタン。日付欄の日が含まれる週（月曜はじまり）の、チェックした曜日に同じ時間で追加する。
- 追加するときのチェック（だめなら下にメッセージを出して追加しない）：
  - 名前が選ばれていない →「名前を選んでください」
  - 終了が開始より前か同じ →「終了は開始より後にしてください」
  - 同じ人・同じ日に、時間が少しでも重なるシフトがある →「11/16(月) は時間が重なるシフトがあります」
    （重なりの判定：新しい開始 < 既存の終了 かつ 既存の開始 < 新しい終了。14時まで と 14時から は重ならない扱い）
- 追加できたら「11/16(月) 9-14 を追加しました」や「3日分追加しました」と出す。

カード3：自分のその週のシフト一覧
- 「◀ 前の週」「11/16(月) 〜 11/22(日)」「次の週 ▶」と「合計 〇 時間」
- 表：日付（土日は色付き）／時間（9 - 14）／時間数（5h）／メモ／「削除」ボタン
- 選んでいる人の、その週のシフトだけを日付・開始時刻の順に出す。ない週は「この週のシフトはまだありません」。
- 名前を切り替えたら一覧も切り替える。追加した日の週を表示する。

カード4：データの保存・移動
- 説明文「データの保存・移動（この端末のブラウザに保存されています）」
- 「JSONで書き出し」ボタン、「読み込み」ファイル選択
- 「選択中の名前を削除」ボタン（赤字）。確認を出してから、その人とその人のシフトを全部消す。

## 5. 1日のシフト表（day.html）— 階段状の表
- 見出し「1日のシフト表（営業 9:00〜22:00）」
- 操作バー：「◀ 前日」、日付表示「11/16(月)」（土日は色付き）、「翌日 ▶」、日付選択、「今日」、「必要人数」(数字入力。初期値2。変えたら保存してすぐ表を描き直す)、「印刷」ボタン（window.print()）
- URLは day.html?date=YYYY-MM-DD の形で、日付を変えたら history.replaceState でURLも変える。

表の作り方（ここが一番大事）：
- <table> で作る。左から「名前」列（幅110px）、「時間」列（幅90px）、その右に30分ごとのマス 26個（9:00〜22:00 を30分で割った数）。table-layout:fixed、最小幅 900px。
- 見出し行：9, 10, 11 … 21 の数字。それぞれ colspan=2（1時間＝2マス）。
- その日のシフトを「開始時刻が早い順 → 同じなら終了時刻が早い順」に並べ、1シフト＝1行にする。これで右下がりの階段状になる。
- 各行：名前（左に色の丸）、時間（9-14）、開始より前の空きマス、色付きの帯（td に colspan＝(終了−開始)÷30分。背景はその人の色、白い太字で「9-14」、メモがあれば「・メモ」）、終了より後の空きマス。
- 空きマスの左の線：毎時ちょうどは実線、30分は薄い点線。
- 一番下の行（tfoot）：「人数」と、30分ごとに働いている人数。必要人数より少ないマスは薄い赤の背景＋赤字。
- 表の下に「出勤 5 人 / 合計 25 時間 / 必要人数(2人)に足りない時間帯：4 時間分（赤）」と出す。
- シフトがない日は「この日のシフトはまだありません（入力する）」と出し、「入力する」は input.html?date=その日 へのリンク。
- 名前が削除済みのシフトは「(削除済み)」灰色で表示する。

## 6. 週間シフト（week.html）
- 見出し「週間シフト（日付を押すとその日の階段状シフト表へ）」
- 操作バー：「◀ 前の週」「11/16(月) 〜 11/22(日)」「次の週 ▶」、日付選択（選んだ日の週の月曜に移動）、「今週」、「出勤者のみ表示」チェック（保存する）、「印刷」
- URLは week.html?date=その週の月曜日。
- 表：縦に名前（登録順）、横に月〜日の7日、一番右に「週合計」。
  - 日付の見出しは day.html?date=その日 へのリンク。土は青、日は赤の文字。
  - マス：その人のその日のシフトを、その人の色の角丸ラベル「9-14」で表示（1日に2つあれば改行して両方）。シフトがない日は薄い灰色の「−」。
  - 今日の列は薄い黄色の背景。
  - 週合計：その人の週の合計時間（15h）。
  - 一番下の行（tfoot）：「出勤人数」として各日の出勤人数（〇人）と、全員の週合計時間。
- 「出勤者のみ表示」がオンなら、その週に1回も出勤がない人は表示しない。
- 表示する人がいないときは「表示するアルバイトさんがいません（シフト入力から登録）」。

## 7. 共通の見た目（style.css）
- 背景は薄いグレー #f5f6f8、文字 #1f2430、補足文字 #6b7280、線 #e3e6eb、強調色 #4f8cff、土曜 #2f6fd6、日曜 #d93f3f
- フォント："Hiragino Sans","Noto Sans JP","Yu Gothic",sans-serif、15px
- 本文は最大幅1200px で中央寄せ、内側の余白16px
- 白いカード（角丸10px、薄い枠線）
- 入力欄・ボタンは角丸6px。メインボタンは青背景・白文字
- メニューは黒（#1f2430）で画面上に固定（position:sticky）
- 印刷するとき（@media print）はメニュー・操作バーを隠し、帯やラベルの色がそのまま印刷されるようにする（print-color-adjust:exact）
```

## WEBで公開する手順（どちらか1つ）

### A. Netlify Drop（いちばん簡単・無料）
1. https://app.netlify.com/drop を開き、無料アカウントを作ってログインする。
2. 6つのファイルが入ったフォルダを、画面にドラッグ＆ドロップする。
3. 数秒で `https://〇〇〇.netlify.app` のアドレスができる。これを開けば週間シフトが出る。

### B. GitHub Pages（無料）
1. GitHub で新しいリポジトリを作る（Public にする）。
2. 「Add file」→「Upload files」で6つのファイルをアップロードし、「Commit changes」を押す。
3. 「Settings」→「Pages」→「Branch」を `main`、フォルダを `/ (root)` にして「Save」。
4. 数分後に `https://ユーザー名.github.io/リポジトリ名/` で開ける。

## 必ず知っておくこと（MVPの限界）

- **データは、入力したスマホ・パソコンのブラウザの中にだけ保存されます。** WEBで公開しても、アルバイトさんがそれぞれのスマホで入力した内容は、ほかの人の画面には出ません。
- 今の形での使い方は「店の共用タブレット・パソコン1台で、全員が入力して見る」です。
- ブラウザの履歴やサイトデータを消すとシフトも消えるので、ときどき「JSONで書き出し」でバックアップしてください。
- 各自のスマホから入力して全員で同じ表を見たい場合は、次の段階として「データを共有で保存する仕組み（例：Googleスプレッドシート＋Google Apps Script、Firebase など）」が必要です。ChatGPTには、完成したあと同じチャットで次のように頼みます。

```
次の段階です。今のアプリはデータを localStorage に保存していますが、
アルバイトさんが各自のスマホから入力して、全員が同じシフト表を見られるようにしたいです。
Googleスプレッドシートと Google Apps Script を使って、データを共有で保存する形に変えてください。
- 画面と機能は今のままにして、common.js の loadData / saveData の部分だけを置き換える方針でお願いします。
- スプレッドシートの作り方、Apps Script のコード、公開（デプロイ）の手順を、初心者向けに順番に書いてください。
- 同時に2人が保存したときにデータが消えないようにしてください。
```
