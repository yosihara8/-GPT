個人情報漏えい等 対応手順書

対象サービス：SagaMap（サガマップ）　運営者：JapanAI研修　作成日：2026年10月10日　版：第1版

🚨 漏えいに気づいたら、まずこの 5 つ

  1. 慌ててデータやログを消さない（原因調査と報告に必要です）
  2. 被害の拡大を止める：パスワード・鍵を変更し、必要ならサイトを一時停止（→ 手順 2）
  3. メモを取り始める：気づいた日時・内容・行ったことを時刻つきで記録（→ 様式 8）
  4. 3〜5 日以内に、個人情報保護委員会へ「速報」を出すか判断する（→ 手順 4）
  5. 迷ったら報告する側に倒す。判断に迷う点は委員会の相談窓口や弁護士に相談する

1. 目的と対象

本手順書は、SagaMap で取り扱う個人情報について、漏えい・滅失・毀損（以下「漏えい等」）が発生した、またはそのおそれがある場合に、被害を最小限にし、個人情報保護法に基づく報告と本人への通知を確実に行うための手順を定めます。

SagaMap で扱う主な個人情報保管場所
お客さま：氏名、メールアドレス、パスワード（ハッシュ化）、興味のある業種、利用履歴、お気に入りデータベース（Neon・アメリカ）
サーバー（Vercel・アメリカ）
事業者：氏名、メールアドレス、パスワード（ハッシュ化）、店舗情報、Stripe の顧客 ID
位置情報：約 100m 単位に丸めた匿名の記録（個人とは結びつかない形）
カード情報運営者は保持していません（Stripe が直接管理）
月次バックアップ（メール添付）運営者のメールボックス・ダウンロード先の端末

3. 報告・通知が「義務」になるケース

次のいずれかに当たる漏えい等（おそれを含む）は、個人情報保護委員会への報告と本人への通知が義務です（個人情報保護法 第26条、施行規則 第7条）。

①要配慮個人情報（病歴・犯罪歴など）の漏えいSagaMap では原則取得していません
②財産的被害が生じるおそれ（クレジットカード番号・ネットバンキングの ID など）カード情報は保持していないため通常は対象外
③不正な目的による漏えい（不正アクセス、ウイルス、内部不正、盗難など）件数に関係なく対象。SagaMap で最も起こりやすいケース
④1,000 人を超える本人の情報の漏えい誤送信・設定ミスでも対象
報告の期限　速報：漏えいを知った時からおおむね 3〜5 日以内　／　確報：30 日以内（③ 不正目的の場合は 60 日以内）
報告が義務でない場合（例：数名へのメール誤送信で、すぐ回収・削除を確認できた）も、本手順に沿って記録を残し、本人へのおわびと説明を行います。

4. 対応の流れ

発見
0 時間
① 発見・第一報
  • きっかけの例：管理画面の「エラー」「操作記録」に見覚えのない操作／利用者からの連絡／各サービスからのセキュリティ通知／身に覚えのないログイン通知
  • 気づいた日時、内容、情報源をすぐ記録する（様式 8）。この時点が「知った時」＝ 期限の起点
〜1 時間
② 被害拡大の防止（初動）
  • Vercel：怪しいデプロイがあれば以前の正常なデプロイに戻す（Deployments → Promote）。必要ならプロジェクトを一時停止
  • Neon：データベースのパスワードをリセットし、新しい接続文字列を Vercel の環境変数に設定
  • Vercel の環境変数 NEXTAUTH_SECRET を新しい値に変更（全員が強制ログアウトされる）
  • CRON_SECRET・RESEND_API_KEY・STRIPE_SECRET_KEY（Stripe ではキーのロール）を再発行
  • 運営者アカウント（管理画面・Vercel・Neon・GitHub・Stripe・Google）のパスワード変更と二段階認証の確認。不要なアクセストークンを削除
  • メール誤送信の場合：送信先に削除を依頼し、削除したことの返信をもらう
〜24 時間
③ 証拠の保全と事実の調査
  • 保全：Vercel のログ（Logs）、管理画面の「操作記録」「エラー」、Neon の操作履歴を画面保存・書き出しする。月次バックアップのファイルも保管
  • 調べること：何が（項目）／何人分／誰の（お客さま・事業者）／いつから・いつまで／どこから（原因・経路）／二次被害の有無
  • 必要なら Neon の「時点復元（Point-in-time restore）」で漏えい前の状態を確認する
3〜5 日以内
④ 報告の判断と速報
  • 手順 3 の ①〜④ に当たるか判断する。「おそれ」の段階でも対象。迷う場合は委員会の相談ダイヤルへ
  • 対象なら、委員会の「漏えい等報告フォーム」で速報を提出（その時点で分かっている範囲で可）
  • 犯罪の疑いがあれば警察（#9110・サイバー犯罪相談窓口）に相談
速やかに
⑤ 本人への通知
  • 漏えいした本人にメールで通知する（文例は手順 6）。連絡がつかない人が多い場合は、サイトのお知らせで公表して代替する
  • パスワードの漏えいのおそれがあれば、パスワードの再設定をお願いする
  • 問い合わせ窓口（ai.prompt.biz@gmail.com）での対応を準備する
30 日以内
（不正目的
60 日以内）
⑥ 確報と再発防止
  • 調査結果をまとめ、委員会へ確報を提出（速報と同じフォーム）
  • 原因に応じた再発防止策を実施し、本手順書・プライバシーポリシーを見直す
  • 対応記録（様式 8）は 3 年以上保管する

5. 報告する項目（速報・確報）

1概要（いつ・何が起きたか）6原因
2漏えい等した個人データの項目7二次被害またはそのおそれの有無と内容
3漏えい等した本人の数8本人への対応の実施状況
4発生した日・発覚した日9公表の実施状況
5発覚の経緯10再発防止のための措置

速報の時点で分からない項目は「調査中」とし、確報で埋めます。

7. 平時の備え（予防）

  • Vercel・Neon・GitHub・Stripe・Resend・Google のすべてで二段階認証を有効にする
  • 管理画面の初期パスワードを変更済みにしておく。パスワードを使い回さない
  • API キー・トークンをチャットやメールに貼らない（貼った場合はすぐ削除・再発行）
  • 毎月 1 日に届く自動バックアップは、ダウンロード後に安全な場所へ保管し、メールは削除する（個人情報を含むため）
  • 管理画面の「エラー」「操作記録」を月 1 回確認する
  • 本手順書を年 1 回見直し、連絡先が最新か確認する
