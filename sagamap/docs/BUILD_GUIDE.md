# 佐賀観光マップ 制作手順書

「佐賀観光マップ」（https://www.saga-kanko-map.com）を、企画から本番運用・自動保守まで作り上げた手順を、実際のやり取りの順にまとめたものです。
同じ流れで別のサイトを作るときは、`docs/MASTER_PROMPT.md`（Claude Code に 1 回で渡せるプロンプト）を使ってください。

## 1. 企画・要件をまとめて渡す

最初に、次の項目を 1 つの文章にまとめて Claude Code に渡しました。

- **事業コンセプト**：「佐賀の個人事業主とお客さんを結ぶ観光マップ」。集客に悩むお店と観光客を地図上で結ぶ。
- **利用者の種類**：お客さま（無料会員）／事業主（無料・有料プラン）／運営者（オーナー 1 人）
- **登録の流れ**：お客さまと事業主で登録ページを分ける。入力項目を決める。
- **プラン**：無料（1 店舗の掲載）・有料（月額 3,980 円：クーポン・広告・SNS 連携・紹介割引）。紹介 10 名で翌月 2,980 円。
- **必須機能**：地図とピン・現在地から近いお店・おすすめ（簡易 AI）・人の流れの可視化・クーポン・広告・紹介プログラム・決済・お知らせメール。
- **技術**：Next.js＋TypeScript＋Tailwind CSS、PostgreSQL（PostGIS）、NextAuth、Stripe、Resend。
- **出力物**：画面・API・DB の構造・環境変数のサンプル。

**学んだこと**：最初の要件は細かいほど良い。ただし作り始めてから見えることが多いので、「後から何度も直す」前提で進める。

## 2. 作る前の確認

- サイトの URL（独自ドメイン）を自分で決めたいので、作る前に確認してもらった。
- **サイトの名前**を決めて固定する（途中で「SagaMap」など別の名前に変わってしまったため、のちに「名前は佐賀観光マップだけ」と仕様メモに書いた）。

## 3. 試作品（MVP）を作る

Claude Code が一式を作成：

- お客さま登録・事業主登録・ログイン（メール＋パスワード、Google ログイン）
- 地図（ピン・クーポン配信中のお店は赤）、近くのお店、おすすめ、経路
- 事業主ダッシュボード（店舗情報・統計・クーポン発行・広告出稿・紹介プログラム・プラン）
- DB の構造（db/schema.sql）と、デプロイ時に自動で適用する仕組み（scripts/migrate.mjs）
- 架空のデモデータ（本番前にすべて削除）

## 4. 公開の準備（インフラ）

初心者でも進められるよう、画面ごとに 1 つずつ確認しながら設定した。

1. **GitHub**：コードの保管場所（リポジトリ）。Claude Code が push する。
2. **Vercel**：サイトを公開する場所。GitHub のリポジトリを読み込み（Import）、ルートフォルダを `sagamap` にする。
   - ビルドのエラーは、Vercel の「Deployments」のログを貼って Claude に直してもらう。
3. **Neon（データベース）**：Vercel の「Storage」→ Neon を作成し、プロジェクトに接続（環境変数 `DATABASE_URL` などが自動で入る）。
4. **地図**：最初は Google マップを使う予定だったが、設定が複雑なため **国土地理院の地図（無料・登録不要）** に変更。Google マップは任意で使える形にした。道案内は OpenStreetMap の道案内サーバー、住所から位置は国土地理院の住所検索。
5. **環境変数**：`NEXTAUTH_SECRET`・`CRON_SECRET` など。値は Vercel の画面で入れる（**会話に秘密の値を貼らない**）。

**学んだこと**：
- 外部サービスの画面は説明と違うことがよくある。画面の文字をそのまま貼ると、正しい場所を案内してもらえる。
- API キーやトークンを会話に貼ってしまったら、必ず作り直す。

## 5. 運営者の管理画面とセキュリティ

- **管理画面（/admin）**：事業者・店舗・お客さまの一覧、CSV 書き出し、代理ログイン、操作記録、掲載チェック、エラー一覧、バックアップ。
- **運営者はオーナー 1 人だけ**。追加できる画面を作らない。お客さま・事業主の画面に管理画面へのリンクを置かない。
- **管理画面のログインは独立**（専用の Cookie。お客さま・事業主のログインとは別）。パスワードを忘れたときの再設定、二段階認証、ログイン通知。
- **セキュリティ**：ログインの試行回数の制限、パスワードの強さの確認、パスワード変更でほかの端末のログインを無効化、Google ログインの乗っ取り対策、画面の安全設定（CSP など）。
- **自動処理**：毎月の DB バックアップ（メール）、毎晩の掲載チェック（景品表示法・薬機法に当たる表現）、毎月の帳簿（Excel）、毎週金曜のお知らせメール。
- **情報漏えい対応手順書**（docs/情報漏えい対応手順書.pdf）。

## 6. 有料化と法律の準備

- 「有料化に必要なやることリスト」を作り、終わったものを消し、進めやすい順に並べ直した。
- **利用規約・プライバシーポリシー・特定商取引法に基づく表記** を作成。
- メールの末尾に送信者の情報（特定電子メール法）、外部送信の公表（電気通信事業法）、外国の委託先の記載（個人情報保護法）。

## 7. 本番の設定（外部サービス）

1. **独自ドメイン**：Vercel の「Domains」で購入（saga-kanko-map.com、自動更新を確認）→ プロジェクトに追加 → www に転送。
2. **メール（Resend）**：送信元ドメインを追加 → 表示された DNS レコードを Vercel の DNS に追加 → 「検証済み」になったら、テストメールが届くことを確認。
3. **決済（Stripe）**：アカウント作成 → 本人確認・口座登録 → 商品と料金（3,980 円・2,980 円）を作成 → 料金 ID・シークレットキー・Webhook の秘密を Vercel の環境変数へ → テスト申し込み・解約を確認 → カスタマーポータル（解約・カード変更）。
4. **Vercel Pro**：お店から料金をいただく商用サイトは有料プランが必要。

**学んだこと**：設定値を貼り付けるとき、前後の空白や「NAME=」まで入ってしまうことがある。アプリ側で自動的に取り除くようにした。

## 8. デザインの作り込み

- 「いかにも AI で作ったデザイン」を避けるため、いくつかの方向性を出してもらって選んだ。
- 観光の色（藍・朝焼け・柿右衛門の赤・嬉野茶・黄金・白磁）、明朝の見出し、有田焼の唐草、佐賀の一枚絵、熱気球のロゴ。
- お客さま（藍）・事業主（深緑）・運営者（紫）で画面の色を分けた。
- 「60 点」「100 点にして」と率直に伝え、何度も作り直してもらった。最後に「統一感・細かいズレ 100%」の総仕上げ。
- 決まったデザインは **仕様メモ（CLAUDE.md）に書いて崩れないようにした**。

## 9. 使いやすさ・売れる仕組みの作り込み

目的を「**登録してくれた事業主の売上が上がること**」に置き、お客さまの 1 回目・2 回目・3 回目のタップで何が見たいかを考えて作り込んだ。

- 地図の画面を 1 ページで完結（地図・一覧・お店のページ・経路・クーポン）。タップ数を減らす。押しても反応しない場所をなくす。
- クーポンの種類を制限しない（％引き・円引き・特別価格・特典）、先着・初回限定・何度でも。
- 写真（無料 3 枚・有料 20 枚、横にスライド）、メニュー、設備、支払い方法（カード・バーコード・交通系 IC）、営業カレンダー（臨時休業・特別営業）。
- SNS 連携（LINE・Instagram・Threads・Facebook・X・YouTube・TikTok）と宣伝ボタン（投稿文にお客様登録のリンク）。
- お知らせは見たら既読、使い方ガイド、開いているタブに色、パスワードの表示ボタン、「ログアウト」は文字で。
- 広告の効果は人数で（見た人・タップした人・お店に行こうとした人）＋「数字の見方」。

**学んだこと**：変更のたびに「使えるか・使いやすいか・競合と比べてどうか」を確認するよう指示すると、細かい抜けが減る。

## 10. 集客を増やす機能

- **レジ横 QR ポスター**（読み取りでそのお店の紹介として会員登録）
- **イベント特集**（バルーンフェスタなど。イベント限定クーポン）
- **事業主への月次レポートメール**
- **特別招待**（管理者だけが発行、人数無制限・3 日間有効。有料機能を期限なしで無料。やめると戻れない注意）

## 11. 法令の総点検

チェック項目の一覧を渡し、「抜けているところは直す・分からないことは確認する」と指示した。

- **特商法**：価格・価格以外の費用・支払方法と時期・提供時期・申込期限・自動更新と解約期限・解約方法・返金・不具合時の対応・動作環境。氏名・住所・電話は「請求があれば遅滞なく開示」。申し込みボタンの直前に「お申し込み内容の確認」。
- **プライバシーポリシー**：取得する情報・取得方法・具体的な利用目的・メール配信と停止方法・第三者提供と委託の区別・Cookie・保存期間・安全管理措置・開示等の請求・改定・窓口。
- **お問い合わせフォーム**（お客さま・事業主）と管理画面の一覧・Excel 書き出し。
- **お客さまが自分で退会できるボタン**。紹介ページでお客さまのメールアドレスを見せない。
- 登録フォームに「必須」「任意」の目印と、いたずら防止の注意文。

## 12. 保守の自動化と大きな更新

- **毎日のエラー報告メール**（個人情報は伏せ字）
- **毎朝の自動保守**（Claude の Routine）：デプロイ状態・型・テスト・ビルド・脆弱性を点検し、小さな不具合は直してテストが通れば公開。大きな変更は報告だけ。
- **脆弱性の対応**：next-auth の更新、使っていない機能の停止、Next.js 14 → 16 の更新。
- **復旧手順（docs/ROLLBACK.md）**：Vercel の Instant Rollback と、更新前のコミットに戻す方法。**実際に戻せることを試してから**本番に反映した。

## うまく進めるためのコツ（このプロジェクトで分かったこと）

1. **仕様メモ（CLAUDE.md）を育てる**：決めたこと・承認したデザインは必ず書いてもらう。「覚えておいて」と言うだけでは忘れる。
2. **修正のたびに全体を再テスト**：自動テスト（Playwright で実際にタップ）を増やし続ける。「全部の機能を再テストして」と定期的に頼む。
3. **画面の写真や文字を貼る**：言葉だけより早く正確に直る。
4. **点数で伝える**：「60 点。100 点にして」は効果があった。目的（事業主の売上）も一緒に伝える。
5. **秘密の値は会話に貼らない**：環境変数の画面で直接入れる。貼ってしまったら作り直す。
6. **法律は一覧で点検**：特商法・プライバシーポリシー・特定電子メール法・景品表示法。最終的には専門家の確認を受ける。
7. **戻せる準備をしてから大きな更新**：復旧手順と、戻す練習。
8. **保守は自動化**：エラー報告と毎朝の点検。ただし決済・認証・個人情報・規約は人が判断する。
