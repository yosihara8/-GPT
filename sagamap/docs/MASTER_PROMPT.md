# Claude Code 用：サイトを 1 回の指示で作るプロンプト

「佐賀観光マップ」を作ったときの手順（docs/BUILD_GUIDE.md）と、途中で分かった注意点をすべて入れたプロンプトです。
**使い方**：下の「ここからコピー」〜「ここまでコピー」を、まるごと Claude Code に貼り付けます。
「1. サイトの情報」の【 】だけを、作りたいサイトに合わせて書き換えてください（書けないところは「おまかせ」で構いません）。
いちばん下に、佐賀観光マップで実際に入れた内容の記入例があります。

# 依頼：Web サービス「【サイト名】」を、企画から本番運用・自動保守まで作ってください

あなたは、プロのフルスタック開発者・UI/UX デザイナー・セキュリティ担当・日本の Web 法務に詳しい担当を兼ねたチームです。
私（オーナー）はプログラミングの初心者です。**返答・画面・メール・規約・コミットメッセージはすべて日本語**で、専門用語を使わずに説明してください。

## 0. 進め方（いちばん大事な決まり）

1. **作り始める前に確認する**：下の「1. サイトの情報」で足りない点・決めるべき点（独自ドメイン、サイト名、運営者の表示、料金、決済の方法など）を、選択肢と「おすすめ」を付けて質問してください。私が答えてから作り始めます。
2. **工程（3. 作る順番）ごとに区切る**：1 つの工程が終わるたびに、できたこと・確認方法（リンク）・次の工程を短く報告し、私の「OK」を待ってから次へ進みます。
3. **あなたができる作業はすべてあなたが行う**：コードを書く、テストする、GitHub に push する、公開する、など。私にしかできない作業（外部サービスのアカウント作成・本人確認・支払い・画面での設定）は、**1 画面ずつ、押すボタンの名前と入れる値まで**初心者向けに案内してください。私が画面の文字を貼ったら、それに合わせて案内し直してください（外部サービスの画面は説明と違うことが多いため）。
4. **秘密の値（API キー・パスワード・トークン・Webhook の秘密）を、私に会話へ貼らせない**：外部サービス（Vercel の環境変数の画面など）に直接入れてもらいます。もし私が貼ってしまったら、作り直す手順を必ず案内してください。コード・コミット・報告にも秘密の値を書かないこと。
5. **決めたことは仕様メモに書く**：リポジトリに `CLAUDE.md`（守るべき仕様・オーナー確認済み）を作り、私が決めたこと・承認したデザイン・名前・画面の流れ・法令の判断を、そのつど追記してください。修正の前には必ず読み、仕様を崩さないこと。「覚えておいて」と言ったことも、ここに書きます。
6. **分からないこと・お金や法律に関わることは推測で決めない**：私に確認してください。私に確認せずに、返金・減額などのお金の約束や、規約の重要な文言を決めないこと。
7. **「完成」と言う前に必ず確かめる**：下の「4. 品質の決まり」をすべて通してから報告します。確かめられなかったこと（本番の画面を直接開けない等）は、そのとおりに書きます。

## 1. サイトの情報（★ここだけ書き換える）

- サイト名：【例：〇〇マップ】（画面・メール・規約でこの名前以外を表示しない）
- 独自ドメイン：【例：www.example.com／まだ決めていない】
- 事業コンセプト（1〜2 文）：【誰と誰を、何でつなぐか】
- このサイトのいちばんの目的（判断に迷ったときの基準）：【例：登録した事業主の売上が上がること】
- 地域・言語：【例：〇〇県・日本語（将来は外国語も）】
- 運営者：屋号【　】、お問い合わせのメール【　】、運営者（管理者）は【私 1 人だけ／複数】
- 利用者の種類：【例：お客さま（無料会員）／事業主（無料・有料プラン）／運営者】
- 料金プラン：【例：無料プラン（できること）／有料プラン 月額〇円・税込（できること）／割引の条件】
- 決済の方法：【例：クレジットカードの毎月自動払い（Stripe）】
- 主な機能（思いつくだけ）：【例：地図・お店の検索・クーポン・広告・紹介プログラム・予約リンク・お知らせメール】
- 会員登録が必要な範囲：【例：お客さまは登録してから地図を使う／一部だけ登録なしで見られる】
- 雰囲気・デザインの希望：【例：観光らしい楽しさ。〇〇の色や伝統工芸をモチーフに。いかにも AI で作った見た目は避ける】
- 参考にしたい競合サービス：【例：〇〇、〇〇／おまかせ】
- その他の希望・決まり：【　】

## 2. 技術（特に希望がなければこのまま）

- Next.js（最新の安定版・App Router）＋ TypeScript ＋ Tailwind CSS。アイコンは lucide（絵文字は使わない）
- データベース：PostgreSQL（Neon。位置情報を使うなら PostGIS）。DB の構造は `db/schema.sql` に書き、公開のたびに自動で適用する（何度実行しても壊れない書き方）
- ログイン：NextAuth（メール＋パスワード、Google ログインは任意）。**運営者の管理画面は別の仕組みで独立したログイン**
- 決済：Stripe（サブスクリプション・カスタマーポータルで解約・カード変更・Webhook で状態を反映）
- メール：Resend（独自ドメインから送信）
- 公開：GitHub ＋ Vercel（商用なら Pro プラン）。定期処理は Vercel Cron
- 地図を使う場合：まず無料・登録不要の地図（日本なら国土地理院の地図）で作り、Google マップは任意で切り替えられる形に。道案内・住所から位置の検索も無料のものを優先
- テスト：vitest（計算・判定の部品）＋ Playwright（実際にブラウザで登録・ログイン・タップの全経路）

## 3. 作る順番（工程と、終わったと言える条件）

1. **確認**：「0-1」の質問と、作るものの一覧（画面・機能・データ）を出す。→ 私が OK
2. **試作品（MVP）**：登録・ログイン・主な機能・利用者ごとのダッシュボード・管理画面の骨組み・DB・デモデータ・`.env.example`。→ 手元で全画面が動く
3. **公開**：GitHub・Vercel・Neon・環境変数を、初心者向けに案内しながら設定。→ 公開の URL で動く。ビルドが失敗したら、ログを貼ってもらって直す
4. **運営者の管理画面**：利用者一覧・検索・CSV／Excel 書き出し・代理での画面確認（記録を残す）・操作記録・エラー一覧・バックアップ。運営者は【1 人】に制限し、追加する画面を作らない。一般の画面に管理画面へのリンクを置かない
5. **セキュリティ**（「6.」をすべて）
6. **有料化の準備**：「有料化に必要なやることリスト」（法令・決済・メール・ドメイン・Vercel Pro 等）を、進めやすい順に出す。終わったものは消して並べ直す
7. **法令の書類**（「7.」をすべて）：利用規約・プライバシーポリシー・特定商取引法に基づく表記
8. **本番の外部サービス**：独自ドメイン（購入・自動更新の確認・www への転送）→ メール（送信元ドメインの DNS 設定・届くか確認）→ 決済（本人確認・口座・商品と料金・Webhook・テスト申し込みと解約）→ 本番のキーへ切り替え
9. **デザインの作り込み**（「5.」）：方向性を 3 つほど見本付きで提案 → 私が選ぶ → 全画面に統一して適用
10. **使いやすさ・売れる仕組みの作り込み**：利用者が 1 回目・2 回目・3 回目に押したとき何を見たいかを考え、タップ数を減らす。競合と比べて足りないものを足す。「1. の目的」に効く機能（集客・リピート・紹介）を提案して作る
11. **運用の自動化**（「8.」）
12. **最終の総点検**：全機能の再テスト・法令の点検・デザインのズレの調整・残っている課題の一覧

## 4. 品質の決まり（すべての修正で毎回）

- 型チェック・lint・単体テスト・本番用ビルドを通す。
- **Playwright で実際の操作を確認**：登録 → ログイン → 主な操作 → ログアウトまで、利用者の種類ごとに。**押しても反応しない場所を作らない**（すべてのボタン・カード・リンクを押して確かめる）。
- **スマホ（幅 390px）とパソコン（幅 1280px）の両方**で画面を撮って見比べ、文字の切れ・はみ出し・重なり・ズレを直す。
- 変更のたびに「使えるか」「使いやすいか」「競合と比べてどうか」を確認する。
- 新しい機能・直した不具合には、自動テストを追加する。テストを消す・飛ばすことで通さない。
- 定期的に、全機能をまとめて再テストする。

## 5. デザインの決まり

- 「いかにも AI で作った」見た目（ありがちなグラデーション・絵文字・どこにでもある配色）を避け、プロのデザイナーが作ったような質感にする。地域や業種に合った色・文字・モチーフを使う。
- 色・文字・余白・ボタン・見出しの決まり（デザインの部品）を最初に作り、全画面で使う。決まりは CLAUDE.md に書く。
- 利用者の種類ごとに画面の色を分ける（例：お客さま・事業主・運営者）。開いているページ・タブには必ず色を付ける。
- いちばん押してほしいボタンは 1 色に決める。フォームの最後のボタンは幅いっぱいで大きく。
- 入力欄に「必須」「任意」の目印。パスワード欄に「表示」ボタン。ログアウトは文字で「ログアウト」。
- 専門用語を画面に出さない。説明は短く、大事なところは色付きの文字で。

## 6. セキュリティの決まり（弱めない）

- パスワードは bcrypt で保存。よく使われるパスワードを断る。ログインの試行回数を制限（アカウントごと・接続元ごと）。
- パスワード変更・再設定・「すべての端末からログアウト」で、古いログインを無効にする。
- 運営者は二段階認証・ログイン通知メール・パスワードを忘れたときの再設定（運営者のメールにだけ届く）。
- 登録・お問い合わせ・クーポン利用など、いたずらされやすい操作は回数制限と、機械による送信の対策。
- ログイン後の移動先は自分のサイト内だけ。画面の安全設定（CSP など）。ログインで内容が変わるページは CDN に保存させない。
- 秘密の値は環境変数だけに置く。使っていない機能は止める。ライブラリの脆弱性を定期的に確認する。
- 個人情報は必要な人にだけ見せる（例：事業者に、紹介で登録したお客さまの氏名・メールを見せない）。

## 7. 法令の決まり（日本・通信販売を前提。最後は専門家の確認を勧める）

- **特定商取引法に基づく表記**：販売価格・価格以外の負担（送料・手数料・初期費用がなければ「なし」と書く）・支払方法と時期・提供時期・申込みの有効期限・**継続契約（自動更新・更新日・解約期限）**・解約方法・返品と返金・不具合時の対応・動作環境・事業者の氏名（屋号だけは不可）・責任者・住所・電話・メール。氏名・住所・電話を「請求があれば遅滞なく開示」にするかは私に確認する。
- **申し込みボタンの直前**に「お申し込み内容の確認」（料金・支払い・自動更新・解約・返金）と、規約・特商法・プライバシーポリシーへのリンクを出す。
- **プライバシーポリシー**：事業者・取得する情報・取得方法・具体的な利用目的・メール配信と停止方法・第三者提供（法令の例外）と業務委託の区別・外国の委託先（国名・制度）・外部送信（電気通信事業法）・Cookie・保存期間・安全管理措置（組織・人・物理・技術・外的環境）・開示等の請求方法・改定・窓口。**実装していない機能は書かない**。保存する情報や外部サービスを増やしたら同時に直す。
- **利用規約**：料金・自動更新・解約・禁止事項・違反時の利用停止・退会。
- **特定電子メール法**：お知らせメールは同意を取り、末尾に送信者名・住所・問い合わせ先・配信停止。
- **景品表示法・薬機法**：お店が出すクーポン・広告に「日本一」「最安」など根拠のない表現や効能の表現がないか、自動で点検する。
- **お問い合わせフォーム**（利用者の種類ごと）と、管理画面の一覧・対応状況・Excel 書き出し。
- **利用者が自分で退会できるボタン**（取り消せない注意・本人確認。集計は誰か分からない形で残す）。

## 8. 運用と保守の決まり

- 自動処理：毎月の DB バックアップ（メール）、毎月の帳簿（Excel）、毎日の掲載チェック、お知らせメール、古いデータの自動削除。
- **毎日のエラー報告メール**（直近 24 時間のエラーをまとめる。個人情報は伏せ字。エラーがなければ送らない）。
- **毎朝の自動保守**（Claude Code の Routine を設定）：デプロイ状態・型・lint・テスト・ビルド・脆弱性を点検し、原因がはっきりした小さな不具合だけ直して、テストが全部通ったら公開。決済・認証・個人情報・規約・DB の構造・大きな更新は公開せず、報告だけ。何もなければ「異常なし」。
- **大きな更新の前に復旧の準備**：戻せる時点を記録し、`docs/ROLLBACK.md`（Vercel の Instant Rollback と、コードを戻す手順）を作り、**実際に戻す練習をしてから**本番に反映する。
- 情報漏えいが起きたときの対応手順書を作る。
- 利用者が増えたときの目安（同時に何人くらい使えるか）と、増えたときの対策を説明する。

## 9. 報告のしかた

- 結論を先に、短く。表や箇条書きで。
- 「できたこと」「確認した方法と結果（テストの数など）」「私がやること（あれば、手順付き）」「確認できなかったこと」を分けて書く。
- 確認用のリンク（公開の URL と、変更した画面の URL）を付ける。

**最初の返答では、作り始めずに「0-1 の質問」と「作るものの一覧」を出してください。**
